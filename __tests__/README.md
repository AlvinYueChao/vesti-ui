# 穿搭规则验证测试

## 测试覆盖范围

本测试套件全面覆盖了穿搭规则验证服务的所有功能，包括：

### 1. 有效路径测试 ✅

- **有效路径1**: 上装 + 下装 + 鞋子
- **有效路径2**: 连衣裙 + 鞋子
- **配饰支持**: 所有有效路径都可以添加配饰
- **分层搭配**: 连衣裙 + 外套 + 鞋子
- **多层搭配**: 上装 + 外套 + 下装 + 鞋子

### 2. 无效冲突测试 ❌

- **无效冲突1**: 连衣裙 + 下装（功能属性重叠）
- **无效冲突2**: 连衣裙 + 普通上装（需排除外套分层情况）
- **无效冲突3**: 多个同层级上装（如T恤+衬衫）
- **无效冲突4**: 多个下装（如裤子+裙子）
- **重复单品**: 多个连衣裙

### 3. 无效基础测试 ❌

- **无效基础1**: 上装 + 鞋子（缺少下半身覆盖）
- **无效基础2**: 下装 + 鞋子（缺少上半身覆盖）
- **缺少鞋子**: 任何搭配都必须有鞋子
- **缺少核心单品**: 必须有上装或连衣裙
- **空穿搭**: 没有任何单品

### 4. 特殊规则测试 🎯

- **外套分层**: 外套可以与连衣裙搭配
- **普通上装限制**: 普通上装不能与连衣裙搭配
- **多外套支持**: 可以有多个外套（分层穿搭）
- **subType默认值**: 未指定subType的上装默认为regular
- **配饰灵活性**: 配饰可以添加到任何有效搭配

### 5. 复合错误测试 ⚠️

- **多重冲突**: 同时违反多个规则的情况
- **错误累积**: 验证多个错误能正确识别和报告

### 6. 工具方法测试 🔧

- `isOutfitComplete()`: 快速检查搭配完整性
- `getMissingRequiredCategories()`: 获取缺失的必要类别
- `canAddCategory()`: 检查是否可以添加特定类别
- `getOutfitRules()`: 获取所有穿搭规则
- `isValidCombination()`: 检查组合是否有效
- `getRecommendedCombinations()`: 获取推荐组合

## 测试最佳实践

1. **描述性测试名称**: 清楚地描述测试的场景和预期结果
2. **独立测试**: 每个测试都应该独立运行，不依赖其他测试
3. **边界测试**: 测试边界条件和异常情况
4. **数据驱动**: 使用测试数据来覆盖不同的场景
5. **断言明确**: 每个测试都应该有明确的断言和错误消息
